## Headline structural fact (verified, load-bearing for several scores)

`pub fn build_agent_prompt` (src/sdk/prompt.rs:48) has **no production caller anywhere in the
workspace** at this anchor. Exhaustive `rg 'build_agent_prompt'` over `src/`, all 37 `src/bin/`
binaries, `experiments/`, and `spike/` returns only (a) in-module tests, (b) three integration
test files (`tests/constitution_g3_your_position_prompt.rs:41`, `tests/constitution_g5_action_menu.rs:3`,
`tests/constitution_real12_task_market_action.rs:17`), and (c) a *different private function with the
same name* in `src/bin/market_external_agent_current_kernel.rs:423`. The module doc names the
production consumer as `evaluator.rs` (prompt.rs:42-44 "Caller (typically `evaluator.rs`)"; echoed at
src/sdk/mod.rs:41), but no `evaluator.rs` exists in the repo —
`tests/constitution_real17_evaluator_prompt_provenance_wire.rs:7-9` states verbatim: "The evaluator
source at experiments/minif2f_v4/ was removed in commit 309e026a. The source-grep tests in this file
have been removed." The canonical agent-prompt surface is therefore test-live but production-orphaned.

## Scored dimensions (1-5)

### 1. boundary_wrappability — 3
- The pub surface is minimal: exactly one `pub fn build_agent_prompt` (prompt.rs:48); `rg 'pub fn|pub struct|pub enum'` over the file returns nothing else, and src/sdk/mod.rs:18 exposes it as a plain `pub mod prompt;`. Structurally trivial to wrap.
- But the signature is 10 positional parameters, 8 of them adjacent `&str` (prompt.rs:48-59: `chain_so_far, skill, market_ticker, …, your_position`) — a facade caller can silently transpose arguments with no type-system protection.
- The doc claims "Build the agent prompt from pure state" (prompt.rs:35), yet the function reads **four hidden process-env inputs**: `TURINGOS_PROMPT_VARIANT` (prompt.rs:28), `TURING_STEP_ONLY` (prompt.rs:192), `TURINGOS_DISABLE_MARKET_TOOLS` (prompt.rs:259-262), `TURINGOS_REAL12_TASK_MARKET_AFFORDANCE` (prompt.rs:309-313). A CLI/lib facade cannot inject these explicitly; any wrapper inherits ambient global state, contradicting the stated purity contract.

### 2. error_discipline — 3
- The function is an infallible String builder: zero `unwrap/expect/panic!` in production code (the only `expect` hits are test-side at prompt.rs:514 and prompt.rs:610, `ENV_LOCK.lock().expect("env lock")`). No `Result` is needed for the happy path; that part is clean.
- However, invalid configuration degrades **silently**: `current_prompt_variant` (prompt.rs:27-33) filters any unrecognized `TURINGOS_PROMPT_VARIANT` value down to control `"v0"` with no warning channel — in an experiment harness a typo'd arm silently becomes the control arm (the classic silent-fallback false-null trap).
- Flag parsing is inconsistent across the same file: variant is lowercased + allowlisted (prompt.rs:30-31), while `TURING_STEP_ONLY` (prompt.rs:192) and `TURINGOS_DISABLE_MARKET_TOOLS` (prompt.rs:259-262) only match the exact string `"1"` — `true`/`"1 "`/`"yes"` silently no-op, with no shared boolean-env helper and no error semantics anywhere.

### 3. invariant_documentation — 3
- Good written contracts: the empty-string-suppresses-block invariant is documented at three sites (prompt.rs:44-47 econ_position, prompt.rs:144-145 pending_peer_reviews "Empty string suppresses the block entirely (mirrors econ_position suppression contract)", prompt.rs:161-162 your_position) and is actually asserted (`test_empty_econ_position_suppresses_block`, prompt.rs:465-476).
- The key determinism invariant — "All variants are additive + opt-in; default behavior is bit-identical to the pre-session-#34 prompt" (prompt.rs:25-26) — is only checked by feature-absence substrings (`v0_default_lists_legacy_tools`, prompt.rs:523-534 asserts `!p.contains("Tactic Search Guidance")` etc.), never by a golden hash/snapshot of the assembled v0 prompt; "bit-identical" is asserted nowhere.
- The "from pure state" invariant (prompt.rs:35) is contradicted by the four env reads cited above — a written invariant that is currently false as stated.

### 4. test_depth — 3
- Real breadth, actually read: 7 top-level tests + 10 `variant_tests` in-module, plus integration gates. Negative paths exist: suppression (prompt.rs:465-476), unknown variant falls back to default (prompt.rs:599-606), v4 omits the rejects block when no errors (prompt.rs:590-597), opt-out set vs unset both exercised (prompt.rs:620-642). `tests/constitution_g5_action_menu.rs:7-25` enumerates all 8 advertised tool schemas in one assertion loop; `tests/constitution_real12_task_market_action.rs:84-121` checks the affordance text including the anti-coercion negative (`!prompt.contains("must trade")`).
- Quality caveats: everything is substring-presence, no golden full-prompt expectation anywhere. `test_prompt_contains_no_example_values` (prompt.rs:405-421) is near-vacuous — it only asserts the literals "50.0"/"100.0" are absent from a prompt built from empty inputs. Source-grep gates (`tests/constitution_n1_agent_economy_a4.rs:563-571` `prompt_src.contains("verify_peer")`; `tests/constitution_shielding_gate.rs:41-54`) pass even if the string only survives in a comment.
- Coverage hole: the `TURING_STEP_ONLY=1` branch (prompt.rs:192-224, ~33 lines including the step-only `verify_peer` schema) has **zero test coverage repo-wide** — `rg TURING_STEP_ONLY` outside prompt.rs hits only ops scripts (`docker/paper1_reproducer/entrypoint.sh`, `tools/run_e1v2_serial.sh`) and handover docs, never a test.

### 5. concurrency_safety — 3
- Production path is lock-free and allocation-only — no `Mutex/RwLock/spawn` outside `#[cfg(test)]`; trivially Send/Sync; the only shared state touched is read-only env access (prompt.rs:28, 192, 259, 309).
- The test suite documents its own hazard honestly: "NOT thread-safe under `cargo test --workspace`; per `feedback_env_var_test_lock` we serialize via a static mutex" (prompt.rs:503-506) with `static ENV_LOCK: Mutex<()>` (prompt.rs:511).
- But the lock discipline is partial: the seven top-level tests (prompt.rs:405-501) call env-sensitive `build_agent_prompt` **without** taking `ENV_LOCK` (which is private to the nested `variant_tests` module) while variant tests mutate the process-global env on parallel threads of the same test binary — currently no top-level assertion observably collides, so it's latent, not active. And `with_variant` (prompt.rs:513-521) is not panic-safe: a panicking body skips `remove_var` and poisons the mutex, so the next variant test dies on `.expect("env lock")` (prompt.rs:514) with a misleading failure.

### 6. dead_code_density — 3
- By markers the file is spotless: `rg 'TODO|FIXME|allow\(dead_code\)|#\[allow'` over prompt.rs returns zero hits; no commented-out code blocks in 663 LOC.
- But the dominant dead-code fact is functional: the module's only pub fn has no production caller (see headline; verified across src/, all bins, experiments/, spike/), its documented consumer was deleted in 309e026a (tests/constitution_real17_evaluator_prompt_provenance_wire.rs:7-9), and the doc references to `evaluator.rs` at prompt.rs:42-44 and src/sdk/mod.rs:41 are stale. The session-#34 v2/v3/v4 experiment injections (prompt.rs:338-394) are live code for an experiment whose harness left the repo.

## Summary

src/sdk/prompt.rs is a clean, lock-free, marker-free 663-LOC prompt assembler with genuinely good inline contract documentation (suppression contracts written and asserted, variant history traceable to sessions/rulings) and a broad substring-assertion test suite covering negative paths — but the audit's controlling discovery is that its single pub fn `build_agent_prompt` is production-orphaned at this anchor: the documented caller `evaluator.rs` was deleted in commit 309e026a, no non-test caller exists anywhere in the workspace, a same-named private prompt builder in src/bin/market_external_agent_current_kernel.rs sends real LLM prompts outside every gate's scan scope, the flagship TURING_STEP_ONLY=1 branch is untested repo-wide, and one registered constitution gate over this surface contains zero tests. For port-readiness this means the heavily-gated "canonical" prompt surface and the actually-executed prompt surfaces have diverged; all six dimensions land at 3 — disciplined craftsmanship undercut by orphaned wiring, hidden env inputs contradicting the stated purity invariant, and silent-fallback configuration parsing.
