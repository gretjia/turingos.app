## Scored dimensions (1–5)

### 1. boundary_wrappability — 4

The pub surface is large (~30 items) but coherent: data types (`LedgerEntry` L197, `LedgerEntrySigningPayload` L236), pure root-fold fns (`append` L299, `map_reduce_tick_map_root` L308, fc3 root family L354–432), storage traits (`LedgerWriter` L474, `LedgerCasView` L656, `L4eReplayView` L703), replay entry points (L767/787/812/1165), codec (L1222/1229), and the `Git2LedgerWriter` backend. Deductions:

- **git2 leaks into the pub API.** `pub fn head_commit_oid(&self) -> Option<git2::Oid>` (L1518), `head_chaintape_l4(repo_path) -> Result<Option<git2::Oid>, _>` (L1523), `advance_chaintape_l4e_to(repo_path, oid: git2::Oid, ...)` (L1534), `advance_chaintape_cas_to` (L1549), `head_chaintape_l4e` (L1570), `head_chaintape_cas` (L1581). Any CLI/lib facade wrapping these must take a git2 dependency or convert. The trait-level mitigation exists and is good: `head_commit_oid_hex(&self) -> Option<String>` (L491, required no-default method) is the boundary-safe accessor.
- **Hidden type-special-casing in a generic API.** `canonical_decode<T>` silently switches to a legacy-fallback decoder when `TypeId::of::<T>() == TypeId::of::<typed_tx::TypedTx>()` (L1232–1239). A facade re-exporting "the canonical codec" inherits behavior that differs per type parameter without that being visible in the signature.
- Replay entry points take 6–8 concrete registry/keypair parameters (`replay_full_transition_with_predicate_binding_and_l4e`, L812–821, carries `#[allow(clippy::too_many_arguments)]` L811) — wrappable, but the facade must thread five crate-internal types.

### 2. error_discipline — 4

Result-discipline is genuinely clean: production code (L1–1758) contains **zero** `unwrap(`/`expect(`/`panic!`/`unreachable!` (verified by awk over the pre-test region; the only non-panicking combinators are `unwrap_or_else(|| predicate_registry.clone())` L838 and `unwrap_or(entry.epoch)` L1018/L1111). All three error enums implement Display + std::error::Error with semantic payloads: `LedgerWriterError::LogicalTGap { expected, got }` (L495–512), `ReplayError` with 10 variants each carrying the failing index `at` plus context such as `TxKindMismatch { envelope_kind, decoded_kind }` (L576–646), `CanonicalCodecError::TrailingBytes { consumed, total }` (L1357–1378). Deductions:

- `BackendCorruption(String)` is a stringly catch-all absorbing ~25 distinct git2 failure modes in `Git2LedgerWriter` (e.g. L1449 "repo init", L1663 "canonical_encode", L1719 "commit", L1733 "C1 alias ... update") — callers cannot discriminate programmatically.
- `ReplayError::CasMissing { at: 0 }` is reused as a placeholder for conditions that are not CAS lookups and not at index 0: `LedgerCasView` default methods (L663, L674), `EmptyL4eReplayView::prefix_root` (L717), `RejectionEvidenceWriter::prefix_root` (L731, L735). Most are re-wrapped with the correct index at the replay call sites (e.g. L875 maps to `at: i`, L913/L925 map to `Transition { at: i, ... }`), but the raw trait surface emits misleading indices.

### 4. test_depth — 4

18 in-module tests read in full; assertion quality is high and adversarial, not tautological:

- Tamper matrix: parent_state_root (L1867–1872), parent_ledger_root without recomputing resulting root — explicit transplant simulation (L1877–1884), resulting_ledger_root (L1889–1894), signature (L2271–2281).
- The tx-kind-mismatch test re-signs the tampered envelope and recomputes the resulting ledger root so that ONLY stage 6.5 can be the failure path (L2345–2365) — proper failure-isolation, with exact variant assertion `TxKindMismatch { at: 0, envelope_kind: Verify, decoded_kind: Work }` (L2377–2384).
- State-unchanged-after-rejection asserted (`w.len()==1` and `head_commit_oid()==pre_oid` after a gap rejection, L2064–2065); cold-restart recovery (L2071–2094); CAS reopen round-trip (L2287–2327); trailing-bytes rejection (L2469–2472).

Deductions: (a) **no pinned golden digest vector** — the domain-separation strings `turingosv4.ledger_entry_signing.v1` (L252) and `turingosv4.ledger_root.v1` (L301) appear ONLY inside this module (rg across src/ + tests/); all digest tests are self-consistency (clone equals clone L1826–1828, encode-twice byte-equal L2465–2466), so a field-reorder in `canonical_digest` would pass every test and only fail on replay of pre-existing tapes. (b) One `#[ignore]`d empty placeholder test `sequencer_serial_replay_byte_identity` (L2447–2454). Integration coverage exists outside (tests/tb_14_chaintape_smoke.rs L166 runs `replay_full_transition_with_predicate_binding`; tests/constitution_head_t_c2_multi_ref.rs L63).

### 5. concurrency_safety — 4

The module itself contains zero `Mutex`/`RwLock`/`spawn`/`unsafe`/`Arc` (rg confirmed empty). Mutation is `&mut self` (`LedgerWriter::commit` L475), and `Git2LedgerWriter` deliberately stores only `PathBuf + Option<Oid> + u64` (L1406–1412), re-opening the repo per operation (`open_repo` L1511) — this is what makes the `LedgerWriter: Send + Sync` bound (L474) satisfiable despite git2's non-Sync `Repository`. Callers wrap it as `Arc<RwLock<dyn LedgerWriter>>` (src/state/sequencer.rs:4997, src/runtime/mod.rs:793), so single-process locking lives at the boundary. Deductions:

- **Multi-instance / multi-process write race is unguarded and undocumented.** `commit` validates against the in-memory cache `self.len` (L1653) and force-updates refs (`repo.commit(Some(CHAINTAPE_L4_REF), ...)` L1710–1719; C1 alias `repo.reference(..., true, ...)` L1726–1731 with force=true). Two `Git2LedgerWriter` instances opened on the same path would both pass the gap check at the same `len` and the second would silently orphan the first's commit. The single-writer assumption is nowhere stated in the module doc or trait doc.
- Blocking behavior (git I/O under the caller's RwLock write guard) is implicit; the partial-failure window between the C2 ref commit and the C1 alias mirror is at least documented with its repair path (L1704–1709, repair-on-open L1452–1485).

## Summary

transition_ledger.rs is one of the most disciplined modules I have audited in this codebase: production code is panic-free end-to-end (zero unwrap/expect/panic before the test mod at line 1759), every key invariant (append purity L296-298, 9-stage replay contract L743-766, Q9 derivative exclusion L229-234, frozen bincode wire choices L1205-1212, deterministic git time L1690) is both written down and backed by an adversarial test that isolates the exact failure stage (the re-signed tx-kind-mismatch test at L2345-2384 is exemplary), and dead-code density is effectively zero. The four deductions that matter for porting are: git2::Oid leaking through six pub functions plus a TypeId-special-cased legacy decode path hidden inside the generic canonical codec (boundary); a stringly BackendCorruption catch-all and CasMissing-at-0 placeholders (errors); the absence of any pinned golden digest/wire vector, meaning byte-format drift is undetectable by the test suite alone (tests); and an undocumented single-writer assumption in Git2LedgerWriter whose force-ref updates make a second writer instance silently orphan commits (concurrency). None of these are live defects on the current single-process runtime, but all four are exactly the seams that a CLI/lib facade port will stress.
