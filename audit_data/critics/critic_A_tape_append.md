## 1. boundary_wrappability — **3/5**

Can it be wrapped by a CLI/lib facade without leaking internals? Mostly, but three leaks bite a porter.

Evidence:
- **git2 types leak through the pub API.** `pub fn head_commit_oid(&self) -> Option<git2::Oid>` (transition_ledger.rs:1518), `head_chaintape_l4(repo_path: &Path) -> Result<Option<git2::Oid>, ...>` (:1523), `advance_chaintape_l4e_to(..., oid: git2::Oid, ...)` (:1534), `advance_chaintape_cas_to` (:1549), `head_chaintape_l4e` (:1570), `head_chaintape_cas` (:1581). Any facade re-exporting these must make `git2` a public dependency. The trait itself is clean — `LedgerWriter::head_commit_oid_hex(&self) -> Option<String>` (:491) deliberately maps OID to a plain hex string — but the six inherent `Git2LedgerWriter` methods bypass that discipline.
- **Compile-time repo-layout coupling.** `constitution_source_hash()` does `h.update(include_bytes!("../../../constitution.md"))` (:345-349). The module cannot compile outside a tree where `constitution.md` sits exactly three levels up — a direct port hazard.
- **Deep-parameter replay entry points.** `replay_full_transition_with_predicate_binding_and_l4e` takes 8 parameters spanning `QState`, `LedgerCasView`, `PredicateCasView`, `L4eReplayView`, `PinnedSystemPubkeys`, `PredicateRegistry`, `ToolRegistry` (:812-821, with `#[allow(clippy::too_many_arguments)]` at :811). A facade must be able to construct all seven type families to call replay.
- Mitigating: the storage seam is genuinely wrappable — `pub trait LedgerWriter: Send + Sync` returns only `Hash`/`Option<String>` (:474-492), and `pub trait LedgerCasView` (:656-677) decouples replay from the concrete `CasStore` ("Anything that can hand back the bytes for a `Cid` satisfies this", :653-655). Error enums are self-contained (no git2 types inside `LedgerWriterError`, :495-499).

## 2. error_discipline — **4/5**

Result-threaded throughout; zero panic surface in production code.

Evidence:
- `awk 'NR<1759 && (/unwrap\(/||/expect\(/||/panic!/)'` over the file returns **nothing**; every one of the 40+ `expect`/`unwrap` hits is inside `#[cfg(test)] mod tests` (first hit :1860). The three production `unwrap_or` uses are semantic fallbacks, not panics: `unwrap_or_else(|| predicate_registry.clone())` (:838), `system_epoch_of(&typed_tx).unwrap_or(entry.epoch)` (:1018, :1111).
- Error types carry semantics with context fields: `LedgerWriterError::LogicalTGap { expected, got }` (:496), `ReplayError::TxKindMismatch { at, envelope_kind, decoded_kind }` (:611-615), `PayloadDecode { at, reason }` (:619-622), `CanonicalCodecError::TrailingBytes { consumed, total }` (:1361). All three enums implement `Display` + `std::error::Error` (:501-512, :625-646, :1364-1378).
- Deductions: (a) `BackendCorruption(String)` (:498) is a stringly-typed catch-all used for ~25 distinct git failure modes (:1449, :1513, :1619-1639, :1663-1736) — a wrapper cannot match on cause. (b) Underlying errors are erased with `.map_err(|_| ...)` (:684, :689, :698, :913, :925) — the original `CasError` text is dropped. (c) Asymmetric ref-read discipline: `head_chaintape_l4`/`head_chaintape_l4e` swallow ALL errors into `None` via `.ok().and_then(...)` (:1527-1529, :1573-1576), while `head_chaintape_cas` correctly distinguishes `NotFound` from real corruption (:1584-1592). (d) `LedgerCasView` trait default impls return placeholder `CasMissing { at: 0 }` (:662-664, :674) — index is a lie at the trait layer, though call sites re-wrap with the true index (:875, :920-929).

Evidence:

## 5. concurrency_safety — **3/5**

No locks because there is (almost) no shared state — but the one stateful object has an undocumented single-writer assumption.

Evidence:
- `rg 'Mutex|RwLock|spawn|thread|Arc<'` over the file: **zero hits**. The replay family and root-fold functions are pure (`append`, :299-305; `replay_chain_integrity`, :1165-1199) — trivially thread-safe. `pub trait LedgerWriter: Send + Sync` makes the trait boundary explicit (:474). Blocking points are clear: every Git2 operation re-opens the repository (`open_repo`, :1511-1514) rather than holding a handle.
- The gap: `Git2LedgerWriter` caches `head_oid: Option<git2::Oid>` and `len: u64` in memory (:1406-1412) and `read_at` walks `self.len - logical_t` parents from the cached head (:1612-1625). Nothing locks the underlying repo: ref updates use `force=true` (`repo.reference(TRANSITIONS_REF, c2, true, ...)` in the open-time divergence repair :1471-1476; C1 alias mirror after commit :1726-1731). Two writers on the same repo path (e.g. a ported CLI `verify` plus a daemon appender) would clobber refs and desynchronize the cached `len`. The partial-failure window of the two-step C2→C1 dual-ref write is documented and has a repair path (:1452-1457, :1704-1709, :1721-1725), but the single-process/single-writer precondition itself is never stated as an invariant anywhere in the file.
- `open()` mutates refs on what reads as a read path (divergence repair writes `refs/transitions/main`, :1467-1481) — surprising side effect for concurrent openers.

## Summary

`transition_ledger.rs` is one of the more disciplined 2.5k-line files I have audited: zero production panic surface (every `unwrap`/`expect` sits inside `#[cfg(test)]`, first at line 1860), semantically rich error enums with context fields, invariants (append-only fold purity, Q9 derivative exclusion, K2 transplant defense, frozen wire-format choices, no-wall-clock git commits) written down at the governing code and cross-checked by adversarial tests including a re-signed tx_kind-mismatch fixture and a real Ed25519 transplant/epoch matrix; dead-code density is effectively zero. The port-readiness deductions concentrate in three places: the boundary leaks `git2::Oid` through six inherent methods plus an `include_bytes!` relative-path coupling to `constitution.md`; the `Git2LedgerWriter` relies on an undocumented single-writer assumption with force ref updates and an in-memory head/len cache that a CLI-plus-daemon deployment could desynchronize; and byte-stability of the canonical digest/codec is asserted only by same-process double computation, never against a pinned golden vector — the single cheapest high-value hardening before a port. Secondary advisories: the legacy EventResolve decode fallback injects `OutcomeSide::Yes` and quietly breaks the encode/decode bijection the codec doc promises, and the module's "skeleton / NotYetImplemented" status headers are stale enough to mislead a cold reader about maturity.
