# Software 3.0 UX 宪章（P1-UI 信息架构法源，五次裁决产物）

> 2026-06-10 用户裁定：此前一切稿件（r1 三张乃至对 V6 的忠实翻译倾向）犯了
> **Software 1.0/2.0 看板哲学**的根本错误——数据轰炸、无重点。本宪章以 Software 3.0
> 理念重构信息架构。**V6 自此降格为材质语言参考**（星空/玻璃/语义发光/星系隐喻保留），
> 信息密度与层级由本宪章治理。执行 agent 持有设计自主权（用户授予），重大转向呈报。

## 三定律

1. **注意力优先**：每一屏只回答一个问题。产品的首要问题永远是
   **「我现在需要行动吗？对什么？」**——需要裁决的事置顶，其余退后；
   禁止 N 个等权重数字并列乞求注意。
2. **语言优先**：投影的人类形态是**一句话结论**（P1 为确定性模板句，同投影 ⇒ 同句子；
   P6+ 接 R_GENUI level-iii 生成式解读，届时按 R3 戴 generated 徽章），
   永远可下钻到证据事件。"`omega` 的 `wt_sched` 被两个 worktree 检出同一分支，等你裁决"
   远胜 "Conflict: 3"。
3. **安静即成功**：一切健康时界面近乎空——一行 "一切安静，N 个项目在看管中" 加微弱
   星空脉冲。空屏是理想态，不是未完成态。

## 反模式黑名单（命中即设计评审 FAIL）

- 卡片内 5+ 并列数据行；KPI/计数网格；等权重三计数并排展示
- "数据可得就展示"——可得性 ≠ 应展示性
- 要用户自己从数字推断"要不要管"
- 用徽章/颜色装点而非分诊

## P1 表面（信息架构）

### Glance（菜单栏）——一个点 + 一句话
状态点 = 全产品最高分诊级（红=有失败证据 / 黄=等你裁决 / 蓝=agent 工作中 / 灰=未对账）。
点开 = **一句话** + （仅当有事时）注意力项列表（每项一句话，点击直达证据）。
没有三计数网格。

### Home —— Attention Stack（注意力分诊栈）
三段，自上而下，空段折叠不占位：
1. **等你（Needs you）**：每项 = 一句话结论 + 单一主操作（"查看证据"）。
   来源（P1 只读域）：同分支冲突 / prunable 孤儿 / fingerprint 失败 / daemon 断连。
2. **进行中（Working）**：ambient 行——项目名 + 呼吸脉冲 + 一句话现状
   （"2 个 worktree 有未提交改动"）。无数字网格。
3. **安静（Quiet）**：折叠为一行 "其余 N 个项目一切安静"。
全部健康 ⇒ 整个 Home 即一句 "一切安静" + 星空。

### Radar（星系空间视图）——探索性下钻，非首页
V6 星系材质全保留：星云=项目、节点=worktree、轨道=主干、语义缩放。
信息层级重构：**节点默认只有 标题 + 状态辉光**；选中聚焦才展开（分支/指纹/证据抽屉）。
注意力项从 Home 点入时直接飞到对应节点并聚焦。

### Onboarding——每屏一个决定
1. **Connect**："把你的 git 世界接进来" + 一个按钮；自动探测 gh 登录态，
   成功即一句 "已通过 gh 接入（@user）"；降级路径逐级可见。
2. **Select**："看管哪些项目？" + 单列表（每 repo 一行：名字 + 一句话近况），勾选即注册。
3. 完成即落 Home，第一句话是 "正在第一次对账…"。

## 与既有法律的关系

- TRUST_STATES × VISUAL_SEMANTICS 不变（徽章/色语义唯一法源）；本宪章治理**何时展示**。
- NAVIGATION_MODEL 五问不变；每屏的"①来看什么"收敛为单一问题。
- R_GENUI R1-R8 不变；语言优先的 P1 模板句是 level-iii 的确定性前身，
  仪式屏（R2）永远在本宪章之外保持全量确定性渲染。
- 双轨反向塑形：注意力分诊所需的异常明细已由 A1_02-A1_06 事件流完整供给，无新内核需求。
