# R1.9 Audit Runbook — turingosv4 移植前质量抽查（本地 session 执行件）

> 本 runbook 是 **P1.9 Runtime Port** 的 R-stage 执行清单。产出 `research/R1.9_memo.md`（审计报告 = R-memo），落盘后 P1.9 的移植 Atom 才解锁（R→D→S 门禁原样适用）。
> 预算护栏：机器扫描 ≤2h；变异抽样 ≤4h CPU（仅 3 模块）；结构化评审 = 双 critic × 5 模块。超预算即停，按已有证据出 memo。

## 0. 基线保护原则（先于一切结论）

**无论审计发现什么：移植永远先做 S1 原样导入、在本仓跑绿全部测试 + 164 道门禁作为基线；一切整修都发生在基线之后，以小 PR 形式、在门禁网内逐颗落地。** 审计决定的是"基线之后的整修地图"，不是"要不要先移植"。这结构性排除了用户担心的"重写导致整体失效"——失效会被基线门禁当场拦截在单颗 PR 范围内。

## 1. 策略空间（证据将把每个模块映射到其一）

- **S1 原样保留**：丑但被边界封装、我们不会改它 → 永不动。封装住的丑不是债，是已折旧资产。
- **S2 绞杀式整修**：边界尚可、内部脏、且在 P2-P8 触碰路径上 → 基线后**首次触碰它的那颗 Atom 顺手整修**（测试网先行加固，再动实现）。
- **S3 移植即重写**（预期极少）：仅当"宪法关键 × 测试浅（变异生存率高）× unsafe/并发隐患"三者同时成立——此时重写不是为优雅，是为正确性。须连同补测试方案单独呈用户停机点裁决。

核心洞见：本产品对内核的要求是**宪法正确性**（replay 确定性、门禁可靠、验签无误、append-only 纪律），不是内部优雅。优雅的优先级 = 触碰概率加权：P2 要碰 signer/verifier、P3 碰 ratify/tag、P6 碰 replay/sequencer——这些模块的质量才是真风险；永不触碰的模块允许永远丑下去。

## 2. 机器扫描（全仓，~1-2h，输出 machine_sweep 数据附进 memo）

在 turingosv4 仓库根目录：

- [ ] **库存**：`cloc --by-file --include-lang=Rust src/`（或 tokei）；`cargo metadata --format-version 1 | jq '.packages[].name'`；bin 目标清单。
- [ ] **clippy 全量清单**（不 -D，要完整分布）：`cargo clippy --all-targets --message-format=short 2>&1 | grep -oP 'warning: [^\[]+' | sort | uniq -c | sort -rn`。
- [ ] **unsafe 普查**：`rg -n 'unsafe' --type rust -g '!**/tests/**' | tee` 逐处记录（数量 + 位置 + 是否有 SAFETY 注释）。
- [ ] **panic 面普查**（区分实现/测试代码）：`rg -c '\.unwrap\(\)|\.expect\(|panic!\(|todo!\(|unimplemented!\(' --type rust -g '!**/tests/**'` per 文件；启动路径 panic 与热路径 panic 分开记。
- [ ] **依赖健康**：`cargo tree -d`（重复依赖）；`cargo audit`（如可装，advisories 清单）。
- [ ] **测试结构**：测试 LOC / 实现 LOC per crate；`rg -l 'proptest|quickcheck'`（property test 使用点）。
- [ ] **热点图**：`git log --pretty=format: --name-only | sort | uniq -c | sort -rn | head -30` × 文件行数 → 修改频次×体积 top20（屎山峰值的最佳先验，也是未来触碰的先验）。
- [ ] **CLI_ABI 预检**（对照本仓 docs/CLI_ABI.md 七律）：`turingos` 全部子命令清单；逐命令 `--json` 支持 y/n；抽 3 条实跑验证 stdout 纯 JSON、stderr 仅诊断、错误是否 typed code。差距即移植后适配工作量。
- [ ] **门禁普查**：164 道宪法门禁的物理形态（脚本/测试/CI 何处）、本地一键运行方式、总数核点——这是移植验收的基准数（少一道即红）。

## 3. 变异抽样（测试深度的硬证据，仅 3 个宪法关键模块）

"测试全过"回答不了"测试够深吗"。`cargo install cargo-mutants`，对三个模块（按实际名定位）：**replay 验证**、**签名验证**、**tape/CAS 追加**：

```
cargo mutants -f <module路径> --timeout 60 --no-shuffle -j 2
```

记录每模块 caught / missed / unviable / **survived 比率**。生存率 >25% = 该模块测试网是浅的（重写它风险高于收益预期，先补测试）；<15% = 测试网可托底整修。CPU 预算 4h 封顶，跑不完就缩 `--shard`。

## 4. 结构化评审（clean-context 双 critic，5 模块）

选样规则（非随机）：热点 top ∩ {replay, tape/CAS, sequencer, signer/verifier, CLI 层} 取 4 个 + 随机对照 1 个。
每模块 rubric，1-5 分，**每个分数必须引用 file:line 证据**：

| 维度 | 问题 |
|---|---|
| 边界可包裹性 | 能否在不泄漏 internals 的前提下被 CLI/lib facade 包住？pub 面是否失控？ |
| 错误处理纪律 | Result 贯穿还是 panic 兜底？错误类型有语义吗？ |
| 不变量文档化 | append-only/确定性等关键不变量有无写下来+断言？ |
| 测试深度 | 断言质量（不只测 happy path？金标还是同义反复？）与 §3 变异数据互证 |
| 并发安全 | 锁纪律/Send+Sync 边界/阻塞点是否清晰 |
| 死代码密度 | TODO/allow(dead_code)/被注释的代码块 |

输出：每 finding 一行 RiskFinding JSONL（对齐 contracts/predicate_result.schema.json 的 `$defs.RiskFinding`，author 标 critic 名）+ 每模块一段人读小结。双 critic 独立跑，分歧处显式列出（不调和——分歧本身是信息）。

## 5. 预注册决策规则（证据 → 策略，机械映射）

> 阈值为初始校准，R-close 时可与用户调整——但必须**先于看结果**就定下来（反 Goodhart：先注册后开箱）。

按模块判定：
- **S1**：边界可包裹 ≥4 且 非测试 panic 面 ≈0（或全在启动路径）且（非宪法关键 或 变异生存率 <15%）。
- **S2**：边界 ≥3、内部 rubric 均分 <3、且在 P2-P8 触碰权重表上 → 登记进绞杀清单（注明触发 Atom）。
- **S3**：宪法关键 且 变异生存率 >25% 且（unsafe 聚集 或 并发 ≤2）→ 单独呈报，附"先补测试再重写"的两步方案，等用户停机点。
- 任何不落入上述的 → 默认 S1 + RiskFinding 留痕。

## 6. 产出（= research/R1.9_memo.md 的章节结构）

①库存与门禁基准数 ②机器扫描数据表 ③变异抽样结果 ④双 critic 评审表（含分歧）⑤**模块决策表（S1/S2/S3 + 触碰权重 + 触发 Atom）** ⑥CLI_ABI 差距清单 ⑦移植三参数建议（历史保留方式 / v4 原仓命运 / 执行路径）供用户终裁。
