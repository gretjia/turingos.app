# R1.9-Delta Triage Runbook — v4 未合并探索的价值与去向审计（双线通用）

> 与 R1.9 的区别：R1.9 是 **main 锚点的质量审计**（S1/S2/S3 移植策略）；本审计是**增量价值 triage**——对 main 锚点之外的未合并探索（PR #280 市场机制 @本地 Mac / PR #283 OS 方向 @omega-vm），回答四问：**它是什么 / 它能活吗 / 它值什么 / 它去哪**。产出是 R1.9 memo §⑦ 参数 2（v4 原仓命运与未合并工作处置）终裁的决策输入。
> 实例化：omega-vm 跑 [PR=#283, 方向=OS] → `research/R1.9B_omega_memo.md`；本地 Mac 跑 [PR=#280, 方向=市场机制] → `research/R1.9C_market_memo.md`（可复用 R1.9 证据与 `handover/reports/UNMERGED_WORK_DEEP_SUMMARY_2026-06-02.md` 底稿）。

## 预注册处置枚举（先于看内容定义，证据→去向机械映射）

| 代号 | 去向 | 适用判据 |
|---|---|---|
| **N** | 改道 turingos.app 新仓 atoms（附预估 atom 数与目标 Phase） | 内核语义新能力 / 工具改良，且与移植后架构兼容；自带测试或可补 |
| **U** | 移植前并回 v4 main（极例外） | 小、独立、修的是 main 锚点已编目的红（如门禁跑器 BSD 修复同构件）；任何大簇不走 U |
| **A** | 归档留参（冻结仓 + handover 文档承载其探索价值） | 实验数据/报告/一次性脚本；结论已被吸收、代码本身无复用价值 |
| **D** | 显式废弃（记录理由） | 死探索 / 与既定 ADR 冲突 / 被更好方案取代 |

边界案例标"边界"并列两可理由，交用户域裁决——**triage 官不替用户判断探索的战略价值，只把证据摆齐**。

## 执行序列

**§1 库存**：本机 OS/工具链版本；PR 元数据（base/head/commits 数/files/±行，`gh pr view` 或 git 对比）；本机 worktree 实况（当前 branch/HEAD、`git status` 脏文件统计、**未推送的本地 branch 清单**——PR 可能只是冰山可见部分）；与 main 锚点 `1f00012d` 的 merge-base 与分叉时长。

**§2 机械生存性**：在探索分支检出态跑 `cargo test --workspace --no-fail-fast` 与 164 门禁套件（结果如实记录，**红不修**——与 main 锚点已编目的 4 红对比，区分"继承红"与"增量新红"）；统计增量自带的新测试文件/用例数。

**§3 语义聚类**：把全部增量（commits + 脏 diff）切成**功能簇**。每簇一张卡：一句话定位｜涉及文件与 ±行｜自带测试 y/n｜依赖 main 没有的什么｜与其他簇的耦合。聚类由内容驱动，不预设分类。

**§4 处置映射**：每簇按预注册枚举给 N/U/A/D + 理由 + （N 簇）预估 atom 数与目标 Phase。

**§5 冲突面（汇总决策的关键）**：增量触碰文件 ∩ R1.9 热点图 top（sequencer.rs / typed_tx.rs / transition_ledger.rs / system_keypair.rs / cmd_generate.rs…）；**双线都触碰的模块单列**（market 线与 OS 线的重叠区是合并风险最高处）。

**§6 用户域问题清单**：需要用户本人裁决的战略判断，逐条列出，不越权代答。

## 反漂移铁律

R1 v4 仓只读（不 commit/rebase/merge/cherry-pick/"顺手清理"）；R2 红不修、只编目；R3 每个论断可溯源（命令+输出文件 或 commit/file:line）；R4 预算 ≤4h 总，到顶按已有证据出 memo；R5 输出唯一 = triage memo（+原始证据目录）；R6 惊喜（增量含密钥/大二进制/历史改写痕迹）即升级头条；R7 不中途问细节，预注册规则即法律。

## 产出与汇总

两份 memo 落齐后，首席架构会话（云端）做**三方汇总**（R1.9 质量审计 + 两份 delta triage）→ 给用户一次性终裁包：参数 1/2/3 + N 簇的 atom 排程 + 冲突区合并次序。
