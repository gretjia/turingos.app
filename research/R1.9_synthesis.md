## 参数 0（新增，汇总后的枢纽决策）：移植锚点前移

**建议：锚点前移至当前 v4 main（终裁时钉具体 rev），配 1 小时「锚点再验证」protocol。**

理由：(a) 您最关心的 OS 成果在锚点之后并入——锚旧等于先排除它再二次移植，双倍工作；(b) 锚点后的 delta 是新近的、经 v4 自身 PR 流程的工作，而 R1.9 的 S-map（S3=0）对锚点前的存量主体依然成立（那部分代码未变）；(c) omega 证据显示 judge.sh pin 在锚点后状态已匹配——R-1a/b/c 红可能已被 main 自愈，基线例外清单有望缩小；(d) 旧锚点的 164 门禁弱于现 main 的 194 门——锚旧 = 移植一部更弱的宪法。
**诚实代价**：锚点后 delta 未经质量审计。缓解 = 锚点再验证 protocol（本地 Mac，干净 clone 当前 main：workspace 测试 + 194 门禁 + pin 全扫 + 新红编目）+ 热点定向核查（老锚→新锚的 hotspot 文件 diffstat；transition_ledger/sequencer 若有重改，仅对其 diff 做定点评审）。不做全量二次审计。
