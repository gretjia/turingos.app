# R0.5_memo — Thin Vertical Slice 调研备忘

P0.5 无外部依赖面（纯本仓脚本），R-stage 重点是**设计裁决**而非外部实证：

## 裁决 1：模拟器是泵，不是生成器

`simulate_event_stream.sh` **重放 fixtures**，不自造事件。理由（M3 单一真相）：若模拟器生成数据，事件形态就有了第二来源，fixture 与生成器必然漂移。fixtures 是数据，模拟器是泵（可选 `--delay` 节奏参数供演示）。

## 裁决 2：渲染器输出确定性 markdown

`render_snapshot_placeholder.sh`：stdin 吃 JSONL → fold 成投影 → 输出 markdown 仪表板。它是未来 SwiftUI Radar 的占位证明件：**contracts → events → projection → human-readable view 全链可走通**。确定性要求：同输入同字节（排序遍历、无生成时刻戳、as_of 只取流内最大 seq）。

## 裁决 3：投影三件套内嵌输出

渲染头部携带 `derive_source: fixture_event_stream` / `schema_version` / `rebuild_command`——投影法律（ADR-003/shipgate #3）在占位渲染器上同样生效，给后续 SwiftUI 实现立样板。

## 裁决 4：golden 快照入库

`fixtures/snapshots/p1_worktree_radar.golden.md` 为提交在案的金标；shipgate p0.5 断言重渲染 == 金标（漂移即红）。其余三条流断言双渲染 sha256 一致（确定性）但不锁金标——它们的视图语义到对应 Phase 再冻结。

## 体验问（双轨法）

本切片的"用户"是后续执行 agent 与评审人：他们第一次能**看见**事件流变成界面状态。徽章用 VISUAL_SEMANTICS 的语义词（verified/active/foreign…）以文本呈现——色彩到 SwiftUI 阶段绑定 design tokens。
